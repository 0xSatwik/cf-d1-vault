# cf-d1-vault API

Machine-readable API reference. /llms.txt and /llm.txt contain identical content.
Base URL: the exact configured PUBLIC_ORIGIN, with no trailing slash.
All responses use Cache-Control: no-store. No secret retrieval/export endpoint exists.
Keys work for any service: github, cloudflare, openrouter, openai, anthropic, google,
composio, pipedream, e2b, daytona, boat, slack, telegram, gmail, google-calendar,
notion, linear, resend, expo, or any custom service slug.

## Authentication and transport

Send Authorization: Bearer <credential> on every authenticated call.
- master: verified against MASTER_SHA256; all administration operations.
- human: verified against HUMAN_SHA256; only GET /whoami, GET /admin/keys,
  POST /admin/keys with action add/rotate/disable/delete/enable/rename.
  Unlock, revoke and agents are master only.
- agent: registered request-only bearer; /mcp only. Cannot unlock itself.
Master is checked before human. Missing/invalid credentials return 401.
A valid human attempting a master operation receives 403.
HUMAN_SHA256 is an optional Worker secret containing the lowercase hex SHA-256
of the owner-chosen human password; absence disables human access.
Never commit or log password values, keys or raw bearer credentials.

All POST admin bodies: Content-Type: application/json, <=32768 bytes,
strict JSON objects (no extra properties). request_id must be a UUID.
Admin errors: {"error":"<fixed_code>"}; error status can include 400, 401,
403, 404, 405, 409, 413, 415 or 503. No caught exception or upstream body is exposed.
An untrusted host, mismatched Origin, or Sec-Fetch-Site: cross-site is refused.
No cross-origin CORS access. Curl may omit Origin.
Identifiers: 1–80 ASCII letters, digits, underscore or hyphen. Key names may also contain spaces (no leading, trailing, or double space).
Service: an identifier. Label: an identifier, unique per service.
Website: must start with https://, no spaces, <=2048 characters; trailing slashes are stripped.
Secret value: 1–2048 printable ASCII characters, no spaces. Any token type works:
classic PAT, fine-grained PAT, API key — the value is opaque.

## Keys

A key is service + label + website + secret. No repo/branch/path policy is stored.
What an agent may do with a key is said in chat, not stored in the vault.

GET /admin/keys
  Returns {"keys":[{"id","service","label","website","enc_version","enabled"}],"limit":100}.
  Ordered by service, label. Metadata only; secret values are never returned.

POST /admin/keys
  {"action":"add","service","label","website","secret","request_id"} -> 200 {"id","service","label","action":"add"}
  {"action":"rotate","service","label","website","secret","request_id"} -> 200, replaces the secret (and website), re-enables the key.
  {"action":"rename","service","label","new_label","request_id"} -> 200, changes the key name. The label is part of the encryption AAD, so the Worker decrypts with the old label and re-encrypts with the new one; the secret value is unchanged. Revokes live grants (agents must re-unlock with the new name).
  {"action":"disable","service","label","request_id"} -> 200, sets enabled=0.
  {"action":"delete","service","label","request_id"} -> 200, hard-deletes the key row plus its grants and write idempotency rows (audit history stays). Cannot be undone.
  {"action":"enable","service","label","request_id"} -> 200, sets enabled=1. Grants revoked at disable time stay revoked.
  Optional "enc_version": 1 or 2, default 1 (the DEK that encrypts the value).
  Errors: label_exists (409) on add of an existing service+label, and on rename to a label another key in the same service already uses; key_missing (404)
  on rotate/disable/delete/enable/rename of an unknown service+label.
  Rotate, disable and rename revoke all live grants for the key. Delete removes them. Enable does not revive revoked grants.

## Agents

POST /admin/agents (master only)
  {"id","token_hash","request_id"} -> 201 {"id","status":"created"}.
  token_hash is the lowercase hex SHA-256 of the agent's request-only bearer.
  The raw bearer is never stored. An agent has no policy; grants authorize it.

## Grants

POST /unlock (master only)
  {"agent_id","service","key_label","request_id"} ->
  200 {"id","agent_id","key_id","service","opened_at","expires_at","revoked_at":null}.
  expires_at is always opened_at + 7200. The grant authorizes one agent to use one
  service + key label for two hours. Replaying the same request_id returns the
  original grant, never a fresh one; a different agent/key/service with the same
  request_id returns idempotency_conflict (409).
  Errors: disabled_or_missing (403) when the agent or key is missing, disabled or revoked.
  No scope is stored in the grant. The repo, task, or endpoint is said in chat.

POST /revoke (master only)
  {"target":"grant"|"agent"|"key","id","request_id"} -> 200 {"status":"revoked"}.
  Revoking an agent revokes its grants. Revoking (disabling) a key revokes its grants.
  "id" is a grant/agent/key UUID, never a key label.

GET /whoami
  {"role":"master"} or {"role":"human"}.

## MCP (POST /mcp, agent bearer only)

Stateless Streamable HTTP. POST only; GET/DELETE return 405; JSON arrays (batches)
are rejected with 400. maxRequestBodySize 32768. Each request creates a fresh
server and transport; there is no session state.
Clients must send Accept: application/json, text/event-stream; without it the
server answers 406 (correct per the MCP spec). Any spec-compliant client works:
Claude Code, Cursor, Cline, Codex, Pi, the MCP Inspector, or an SDK client.
Tool results are JSON text. Tool errors are {"error":"<code>"} with isError true.
A locked call returns {"error":"unlock_required","service","label",
"instruction":"Ask the vault admin to unlock this exact key."} — the agent cannot unlock itself.
Error responses also carry "kind", the error class name (e.g. "TypeError"), for diagnosis.
Every tool call re-checks the grant against D1 primary immediately before dispatch,
and refuses if the key was rotated or disabled since (unlock_required).
Upstream 429/403 returns upstream_refused (or upstream_refused_retry_after_<seconds>);
any other upstream failure returns upstream_failed. Upstream bodies are never returned.

Tools:
- github_read_file: {"key_label","repository","path"} plus optional "branch".
  repository is owner/repo (mixed case allowed). branch, when given, and path are exact; without branch the repo default branch is read. File must be UTF-8
  and <=32768 bytes. Paths under .env, .git, secrets, or ending .pem/.key/.p12/.pfx/.env/.ppk,
  or named id_rsa/id_dsa/id_ecdsa/id_ed25519 (plus .pub variants) are refused
  (sensitive_path). Returns {"repository","path","branch","sha","content"}.
- github_list_issues: {"key_label","repository","page":1-10,"state":"open"|"closed"|"all"}.
  Returns up to 20 issues {"page","issues":[{"number","title","state"}]}, pull requests excluded.
- github_create_issue: only when ENABLE_GITHUB_WRITES=true.
  {"key_label","repository","request_id","title","body"}.
  Returns {"number","status":"succeeded"} or {"status":"<stored>","duplicate":true,
  "instruction":"Never resend with a new ID; the vault admin must reconcile uncertain writes."}.
  A write with an uncertain outcome returns write_outcome_unknown_reconcile_with_admin (503).
- service_request: {"key_label","service","method":"GET"|"POST"|"PUT"|"PATCH"|"DELETE",
  "path","body"?}. path starts with / and contains no "..". body <=32768 characters.
  The Worker calls the key's stored website + path with the decrypted key as a Bearer
  token and returns {"status","body"} (parsed JSON when possible, else redacted text).
  Upstream fetch timeout is 25 seconds (the Workers platform caps a request at
  ~30s wall-clock, so it cannot be raised further); the response text is sliced
  to 32768 characters. The key is never shown to the agent. Use the service and key label from the unlock,
  and the path said in chat.

## Static assets (GET, no auth)

GET / or /index.html -> manual entry page.
GET /manual.js, /style.css -> page assets.
GET /llms.txt, /llm.txt -> this reference (identical).
Response header X-Vault-GitHub-Writes: "true" or "false".

## Storage

D1 tables: keys(id, service, label, website, ciphertext, nonce, enc_version, enabled),
agents(id, token_hash, revoked_at), grants(id, agent_id, key_id, service, opened_at,
expires_at, revoked_at, admin_request_id), audit(id, ts, agent_id, key_id, grant_id,
operation, status, request_id), write_operations(agent_id, request_id, key_id,
fingerprint, status, created_at), admin_requests(request_id, operation, created_at).
UNIQUE(service,label) on keys. grants enforces expires_at = opened_at + 7200 and a
key-service match trigger. Keys are AES-256-GCM encrypted; AAD binds id, service,
label, enc_version. Audit is metadata only, capped at 10000 rows / 1000 per day,
pruned to 7 days.
